## Voice and content notes for whoever integrates this later

This content assumes a technical but time-constrained reader (an enterprise architect, a CTO, a technical buyer) — plain language over jargon, concrete claims over vague ones, and the same prior-art honesty discipline as the rest of this repository (no unqualified "revolutionary" or "first-of-its-kind" language for anything classified `E` or `S` in `patterns/index.yaml`). Any classification-related claim in this content must stay consistent with `research/prior-art-differentiation-matrix.md` — if that matrix is updated in a future research cycle, this content should be revisited too.
