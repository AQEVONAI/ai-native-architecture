# From Patterns to Blueprints: 5 Reference Architectures

Patterns describe one architectural concern well. Real systems need several working together. Our reference architectures show how our 17 patterns compose into deployable blueprints for the scenarios enterprises actually face.

**Grounded Enterprise Knowledge Retrieval** — an AI capability that answers questions from your governed, federated knowledge, with every claim traceable to a source. The starting point for most organizations' first AI-native capability.

**Governed AI Memory & Personalization** — a capability that remembers a user's context across sessions, with the same access-control and retention discipline you'd expect from any other system holding personal data.

**Bounded Autonomous Agent** — an agent that takes real action, within an enforced boundary that doesn't depend on the model "deciding" to follow instructions.

**AI Observability & Evaluation** — the operational backbone every production AI capability needs: full execution tracing, evaluation gates that actually block bad changes, and honest, visible degradation when something upstream fails.

**Composite AI-Native Enterprise Architecture** — the flagship blueprint: how all six domains and all 17 patterns fit together as one coherent system once an organization has multiple AI capabilities in production, sharing infrastructure instead of each rebuilding it from scratch.

## Start narrow, grow into the composite

We don't recommend building the full composite architecture for a first capability — that's usually premature. Start with the single reference architecture that matches your actual first use case, and let the shared infrastructure (especially observability) grow with your portfolio. Our [maturity assessment](maturity-assessment-overview.md) can help figure out where you actually stand today.
