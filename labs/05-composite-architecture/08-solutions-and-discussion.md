A plausible resulting profile: Knowledge: 2-3 (fabric now serves three sources with consistent governance, though full Level 3 requires confirming `E-01` freshness is tuned for the new ticket-system source too), Intelligence: 1-2 (unchanged unless routing/budgeting was specifically extended), Autonomy: 1-2 (two capabilities now have documented, justified assignments, though "consistently applied across the portfolio" for full Level 3 requires the third capability's assignment to hold up under scrutiny too), Control: 2-3 (both agentic-ish capabilities now have real enforcement, Q12's approval-rate diagnostic should be re-run for the new capability's suggestion-confirmation step), Operations: 3 (shared `O-01`/`O-02`/`O-03` genuinely in place across all three, satisfying Level 3's "consistently applied" bar directly), Evolution: 2-3 (the review cycle now aggregates three capabilities, though Level 4's "demonstrated track record of measurable improvement" requires more elapsed cycles than this lab covers).

This is a useful, honest distinction: portfolio growth improves maturity scores unevenly, concentrated in whichever domain had genuinely reusable infrastructure versus domains where each capability still does its own independent work.

## Exercise 2 — The suggestion becomes an action

This requires: reclassifying the workload assistant from A2 to at minimum A3 (execution ready, requiring approval) per `DF-02`'s evidence-based revisiting guidance, backed by the accumulated `O-02` data; adding an execute tool to the Envelope (previously explicitly excluded, per `05-common-pitfalls.md`'s warning about this exact change); and building a `C-02` policy for the execute action. Rather than building a new enforcement point from scratch, the cleanest integration reuses Lab 03's existing ticket-agent enforcement infrastructure directly — the workload assistant's "execute" tool could literally invoke the same underlying `reassign` action Lab 03's agent already has enforced, rather than duplicating that enforcement logic. This also means the workload assistant's execute action would need to carry the confirming manager's identity through to that shared enforcement point, per `C-03`.

## Exercise 3 — A fourth capability, stress-testing the reuse claim

A capability requiring, say, 7-year regulatory retention for a specific class of interaction (as opposed to Labs 01-04's more modest retention windows) would stress-test `I-03`'s retention-policy assumption that retention periods are set per classification but implicitly assumed to be in the weeks-to-months range this lab sequence has used throughout — a 7-year requirement might interact badly with `I-03`'s deletion-request handling (Lab 02's Step 6) if the regulatory retention requirement and a user's deletion right are in direct conflict, which `I-03`'s own Governance Considerations section flags as a real, unresolved tension requiring explicit organizational policy, not a technical default. This would also stress-test `E-01`'s freshness assumptions if the regulated content changes rarely by design (unlike the HR/IT sources) — the existing per-source cadence-tuning discipline from Lab 01 should still apply, but the actual tuning would look very different (much longer intervals, different triggering logic tied to regulatory review cycles rather than organic content updates).

## Exercise 4 — Roadmap this portfolio forward

If Exercise 1's profile shows Control and Autonomy both reasonably matured (Level 2-3) while Knowledge's `E-01` freshness tuning for the new source remains unconfirmed, the prioritization principle's specific trigger (Autonomy outpacing Control) likely no longer applies as sharply as it did in the original assessment — this portfolio's most urgent gap is more likely the less dramatic but still real Knowledge-domain freshness confirmation, or completing Evolution's track record toward Level 4. This is itself the expected, healthy outcome of following the original roadmap correctly: today's most urgent gap should look different from the original assessment's most urgent gap, precisely because that original gap was actually addressed rather than left to accumulate.
